# Native public pools

V3 is an independent testnet template. The V2 single-sponsor contract and legacy UI remain intact. All backing pairs are registered, funded native vaults; a nested receipt-backed pool's fixed claim is in inner receipt units, not dollars.

Provider shares represent only reserve cash. When no protected positions remain, a new provider mints `amount * total_lp / liquidity`; an empty pool starts1:1. Deposits require positive minimum shares. Withdrawals burn a specified part of an authenticated, matured notice and enforce minimum backing output. Both entry and cash withdrawal reject while any protected liability is outstanding. LP ownership is address-bound native accounting, not a transferable NFT. Notices can be cancelled.

Provider fee receipts and acquired receipt principal use separate cumulative distribution indices and separate balances. Each provider stores a snapshot of both indices (the `debt` and `inventory_debt` fields) at every checkpoint: before mint/burn and when claiming. It accrues `shares * (index - snapshot) / 10^12`, rounded down once per checkpoint. Shares are constant between checkpoints, so the sum of provider entitlements never exceeds the distributed balance and every all-or-nothing claim stays payable. Newly minted shares start at the current index, preserving historical distributions for earlier providers. Unallocated integer rounding dust stays in its own receipt balance; it is not cash or a fee entitlement to a later entrant. Tests exercise repeated partial cash exits, entries and tiny distributions, plus conservation of both indices under mixed exits.

Protecting receipts fixes a claim at exact vault redemption value and reserves `ceil(claim * collateral_bps / 10000)`. A partial exit releases a floor-proportional claim and reserve; the final exit consumes every remaining unit. Receipt exits charge only positive gains: provider0–30%, creator0–5%, protocol1%. All fee liabilities are receipt inventory. Backing exits pay the entry claim slice and distribute the surrendered receipts as acquired principal. These receipts can be worth less than the backing spent. Position transfer requires the current owner, not the recipient; a closed position cannot transfer or exit again. `positions(owner)` is a best-effort index of at most 100 open positions the wallet owns. Ids leave it on a full exit, settlement or transfer out. Because anyone can transfer a position to any wallet, a full index skips new ids instead of rejecting protection or transfers; every position remains readable by id, and the recipient can close gifted positions to make room.

All positions share the pool's immutable maturity,300seconds to30days after creation. New protection closes60seconds before that time. Voluntary exits have a60second delay. At maturity, anyone can settle a position into segregated backing credit and distribute its remaining receipts as acquired inventory. This does not push a token transfer to the holder, so a missing or unauthorized trustline cannot block provider withdrawals. Credits are excluded from provider cash and require owner authorization to claim, including to an alternative eligible recipient. Remaining upside is surrendered at maturity.

The pinned factory deploys and initializes atomically, admits only its immutable list of receipt vaults, derives backing from each vault's asset(), namespaces salts by creator, records the deployment, and escrows a10TESTUSD refundable bond. The creator claims that bond after maturity. Factory admin is the protocol fee recipient, not a right to withdraw provider backing.

Storage targets1million ledgers capped by network maximum, with250,000-ledger write thresholds. Deployment extends Wasm code and instances separately and records actual lifetimes. RPC simulations do not renew storage. Neither this nor a30-day term guarantees availability across testnet resets, archival, token authorization changes or contract defects. All contracts are unaudited and all tokens valueless.
